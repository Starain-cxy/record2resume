# 构建内容区索引 Prompt

> 执行方式：把本仓库作为工作目录打开 agent，让它执行本文件，参数在请求中一并给出。文件内的相对路径均以仓库根目录为基准。

## 调用参数

执行时在请求中一并给出下列参数，未提供的项采用默认值。

```text
处理范围：整个内容区（默认）/ 指定文件或目录
更新方式：增量更新（默认）/ 全量重建
索引位置：内容区/索引.md（默认）
额外要求：可选
```

## 提示词正文

你正在维护个人经历知识库的导航索引。请根据内容区中的原始记录，创建或更新 `内容区/索引.md`，使后续 agent 能快速找到相关材料。索引只负责定位，不是第二份事实库，不生成简历候选表述。

### 一、读取范围

1. 先阅读根目录 `README.md`、`内容区/README.md` 和现有 `内容区/索引.md`。
2. 使用文件搜索盘点处理范围内的内容区材料；经历已经拆成目录时，优先阅读其 `README.md`，并识别个人工作记录、项目背景、复盘和附件各自的用途。
3. 增量更新时，只调整受新增、移动、重命名或内容变化影响的索引项，保留其他有效链接和人工备注；全量重建时仍须保留原文能够支持的公开限制。
4. 除索引文件外不修改内容区原文。发现原文冲突、缺失或疑似过期时，在交付说明中指出，不自行改写事实。

### 二、索引应记录什么

根据现有材料，使用简短表格或列表记录：

- 经历或资料名称；
- 指向原始文件或目录 README 的相对链接；
- 已明确的时间、组织和个人角色；
- 便于检索的主题关键词；
- 材料状态，如持续更新、已完成、探索失败、信息不足；
- 原文明确的公开限制或隐私提醒；
- 需要交叉核验的事实资料链接。

复杂经历只保留一个主要入口，并按需补充一至两个关键材料链接，不复制原文中的长段落或实现细节。

### 三、不能写入什么

- 不生成“行动＋方法＋结果”式简历 bullet、求职包装、能力评价或岗位匹配建议。
- 不根据文件名、常识或旧简历补造时间、身份、成果、数字和完成状态。
- 不把团队成果写成本人贡献。
- 不把模板、输出简历或缓冲区材料反向当作事实来源。
- 不因索引中缺少某段经历而删除原始材料。
- 不在索引展开内部代码对象、私有流水线术语、提交哈希、未发表研究细节或不必要的个人敏感信息；只记录定位所需的公开边界。

无法确认但对导航有帮助的字段，可以简洁标为 `待核验`；无助于定位的缺失字段直接省略，避免堆积待办。

### 四、结构建议

索引通常按以下顺序组织，可随内容区实际结构调整：

1. 个人信息与事实资料；
2. 工作经历；
3. 项目与科研经历；
4. 实践经历；
5. 维护说明。

同一综合文件包含多段经历时，可以在索引中分别列出条目，但共同链接到该原始文件。独立项目目录则链接到其 README，并在备注中指出需要继续阅读的个人工作文件。

### 五、完成检查

更新后检查：

- 相对链接是否存在且指向内容区；
- 内容区的重要文件或经历是否有入口；
- 已移动或删除的材料是否仍有失效链接；
- 时间、角色、状态和公开边界是否均能由原文支持；
- 索引是否保持简短，没有演变成格式化事实层或简历文案库。

最后简要报告新增、更新和移除的索引项，以及需要用户核验的冲突或缺失信息。
