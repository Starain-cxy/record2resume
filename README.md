# 经历知识库 → Agent 简历工作流（HTML 模板）

一套「自己记录 → agent 包装 → 模板排版」的个人经历管理与简历生成工作流。

你在**内容区**按自己的习惯记录经历；agent 通过**索引**定位原文，再按目标岗位或申请要求筛选、重构、改写；最后套用**HTML 模板**生成可以直接浏览的网页版简历，并按需导出 A4 PDF。

**使用方式**：把本文件夹作为 agent 的工作目录（项目目录）打开。提示词、模板和你的记录都是仓库内的普通文件，agent 直接读取并执行，不需要把提示词复制粘贴进对话框。

**赶时间？** 直接看 [使用说明太长人类不看版.md](使用说明太长人类不看版.md)。

本仓库只包含**架构**：目录约定、提示词、模板和脚本。内容区里的文件都是占位示例，请替换成你自己的记录。

---

## 解决的问题

- **不擅长包装**：记录、复盘时想得很清楚，真要写成简历却组织不出来。
- **每次生成都不一样**：直接让 agent 写简历，结构、字号、间距每轮都在变，最后没法预期。
- **素材散落**：经历分散在备忘录、Word、聊天记录里，写简历时要重新翻一遍。
- **一份经历要应付多个目标**：投数据分析、投开发、投科研，重点完全不同；每个岗位手改一版，改到后面自己都记不清哪版才是准的。

## 设计理念

这套工作流把整个任务切成三段，每段只由一个角色负责：

| 环节 | 负责方 | 说明 |
| --- | --- | --- |
| 事实记录 | 你 | 内容区是唯一事实来源，按自己的习惯写，不必迁就简历格式 |
| 筛选与包装 | agent | 按目标筛选、重组、改写；但不得创造事实、数字、职责和成果 |
| 版式与输出 | 模板 | 同一份 HTML 同时输出连续网页与 A4 打印版，避免结构每次漂移 |

由此得到四条关键约定：

1. **内容区只记事实和复盘**，不写简历文案；写完不用管它像不像简历。
2. **索引只负责导航**，记录「哪段经历在哪个文件」，不复制事实、不保存候选表述。
3. **agent 动笔前必须回到原文**，索引摘要不能直接扩写成简历；事实与索引冲突时以原文为准。
4. **模板只负责版式**，具体简历从这里复制生成，不把个人信息写回模板。

工作流：

```text
内容区原始记录、事实资料
        ↑
内容区/索引.md（只负责定位）
        ↓  agent 执行 缓冲区/Prompts/HTML简历编写.md + 岗位需求
缓冲区/HTML/templates（版式）
        ↓
output/HTMLOutput 中的具体网页与 PDF
```

## 进化与特化

这是这套流程真正值钱的地方：**内容区越厚，产出越好；同一份内容区，可以对应地生成出很多份特化简历。**

**进化**——每次记录都在为下一次投递攒素材：

- 经历、复盘、数据、踩过的坑都留在内容区，写简历时不必重新回忆；记录越细，可选证据越强。
- 索引让 agent 每次都能准确定位，材料变多也不会变慢或开始遗漏。
- 模板和提示词按你的偏好逐步收紧：第一次可能要来回调间距和取舍，之后同一套参数直接复用。
- 手工改过的措辞同样会沉淀：把上一版成品作为「增量更新基线」交给 agent，你调好的表述会被保留，而不是每次重写一遍。
- 记录是增量的：新增一段经历只需补写原文、增量更新索引，不必重做整个库。

**特化**——事实维护一处，输出按目标分化：

| 目标 | 输出位置示例 | 取舍重心 |
| --- | --- | --- |
| 数据分析实习 | `output/HTMLOutput/数据分析实习-中文-单页/` | 统计建模、数据处理、结果量化 |
| 后端开发实习 | `output/HTMLOutput/后端实习-中文-单页/` | 工程实现、工具链、协作方式 |
| 科研 / 学术申请 | `output/HTMLOutput/科研申请-中文-多页/` | 研究问题、方法、推导与文献 |
| 英文岗位 | `output/HTMLOutput/backend-intern-en/` | 自然英文重写、ATS 友好、不放照片 |

特化只改变「选哪些经历、怎么措辞、给谁看」，不改变事实本身。

## 工作方式（人与 agent 通用）

每个环节都由仓库里的一个文件定义：给 agent 一条执行指令即可完成，人也可以按同样的路径手动操作。

| 任务 | 执行文件 | 读取 | 产物 |
| --- | --- | --- | --- |
| 生成或更新索引 | `缓冲区/Prompts/构建索引.md` | `内容区/` 下的原始记录、复盘与事实资料 | `内容区/索引.md` |
| 生成或更新简历 | `缓冲区/Prompts/HTML简历编写.md` | `内容区/索引.md` → 入选经历的原文、`内容区/事实资料/`、`缓冲区/HTML/templates/`，以及参数指定的上一版成品（可选，增量更新基线） | `output/HTMLOutput/<简历名称>/` 下的 `index.html`、`styles.css` 与 PDF |
| 导出 PDF（可选） | `scripts/export-html-resume-pdf.ps1` | `output/HTMLOutput/**/index.html` | 同目录下的 `.pdf` |

三条对所有 agent 生效的固定约束：

1. 事实只能来自 `内容区/`，不得创造或夸大；索引与原文冲突时以原文为准。
2. 模板只负责版式：具体简历写入 `output/`，不得把个人信息写回 `缓冲区/HTML/templates/`。
3. 输出位置固定为 `output/HTMLOutput/<简历名称>/`，公开版与投递版分开存放。

## 目录结构

```text
.
├── 内容区/                     # 唯一的个人事实来源（本仓库为占位示例）
│   ├── README.md               # 内容区约定
│   ├── 索引.md                 # 只负责定位原文，不是第二份事实库
│   ├── 个人信息.md             # 姓名、联系方式、技能、语言等稳定信息
│   ├── 事实资料/               # 成绩、排名、获奖等可核验事实
│   ├── 工作经历/               # 材料较多的经历拆成独立目录
│   ├── 项目与科研经历.md        # 材料较少时先集中记录在一个文件里
│   ├── 实践经历.md
│   └── assets/                 # 照片、论文、截图等附件
├── 缓冲区/                     # 模板和提示词，不放个人事实
│   ├── HTML/templates/         # HTML/CSS/JS 简历模板（可直接打开预览）
│   └── Prompts/                # 索引维护 + 简历编写提示词
├── output/                     # 生成的简历网页与 PDF
│   └── HTMLOutput/
├── scripts/                    # 批量导出 PDF 的 PowerShell / Node 脚本
├── 使用说明太长人类不看版.md     # 五步版本，只给人类看
├── 使用说明.md                  # 面向第一次使用者的详细步骤与故障排查
└── README.md
```

## 最短上手

1. **准备**：装一个能读写本地文件的 agent 工具（Codex、Claude Code、OpenCode Kimi等任选其一），并把**本文件夹作为它的工作目录／项目目录打开**。agent 需要能读到 `内容区/`、`缓冲区/` 和 `output/`；提示词就是仓库里的文件，不需要你复制粘贴。只有导出 PDF 时才需要 Edge 或其他 Chromium 浏览器。

2. **先看模板**：双击 `缓冲区/HTML/templates/template.html`，右上角可以在「网页视图」和「打印预览」之间切换，先知道成品长什么样。

3. **写经历**：在 `内容区/` 对应文件里用自己顺手的写法把经历记下来——做了什么、遇到什么问题、怎么解决、结果如何、哪些信息不能公开，**不必考虑措辞漂亮**，那是下一步的事。材料多的经历（例如一段实习有多个文件、复盘和附件）在 `内容区/工作经历/` 下建独立目录，并写一个 `README.md`，约定见 [`内容区/工作经历/README.md`](内容区/工作经历/README.md)。

4. **让 agent 出简历**：先执行 [`缓冲区/Prompts/构建索引.md`](缓冲区/Prompts/构建索引.md)（首次全量重建，之后增量更新），再执行 [`缓冲区/Prompts/HTML简历编写.md`](缓冲区/Prompts/HTML简历编写.md) 并附上目标、岗位需求、语言、篇幅等参数。agent 会读取索引与入选经历的原文，套用模板生成简历，写入 `output/HTMLOutput/<简历名称>/`。

5. **导出 PDF**：打开成品目录里的 `index.html`，点右上角「导出 PDF」，打印窗口选 A4、边距「无」、勾选「背景图形」。要批量导出或检查页数就双击 `scripts/export-all-html-resumes.cmd`——**用脚本需要本机安装 Codex**，没有就用浏览器直接打印，成品一致。

第 4、5 步的完整参数、检查清单和排错见 [`使用说明.md`](使用说明.md)，五分钟版本见 [`使用说明太长人类不看版.md`](使用说明太长人类不看版.md)。

改完的成品不要丢：下次生成时把它作为「参考已有简历：增量更新基线」传给 agent，它会保留你调过的措辞、只更新变化的部分；涉及事实的修改则回到内容区改原文。换岗位或换语言也只改参数，详见[进化与特化](#进化与特化)。

## 隐私与公开边界

不需要额外的脱敏流程，保持两条规则就够用：

- 写记录时顺手标一句公开边界（哪段经历、哪个数字、哪个内部名称不能公开），agent 生成时会读到。
- 公开版与投递版分目录生成、不互相覆盖；公开前把敏感字段删掉，而不是藏进 HTML 注释或 `data-*` 属性。

要把仓库本身公开，上传前确认里面没有真实个人信息、联系方式和附件即可。

## 常见问题

**一定要用 agent 吗？**
这套流程假设由一个能读写本仓库的 agent 执行提示词。纯手动当然也可以，但要自己承担索引维护、内容筛选和 HTML 编写；[工作方式](#工作方式人与-agent-通用)表里的路径对人和 agent 同样有效。


**需要安装其他软件吗？**
日常预览和手动导出 PDF 只需要浏览器。批量导出脚本（`scripts/`）需要电脑上安装 Codex，因为它直接调用 Codex 自带的 Node.js 与 Playwright，不在项目里安装任何 npm 包；没有 Codex 时用浏览器的「打印 → 另存为 PDF」即可，效果相同。详见 [`scripts/README.md`](scripts/README.md)。

**可以删掉用不到的目录吗？**
可以。最小可用集合是：`内容区/`、`缓冲区/Prompts/构建索引.md`、`缓冲区/Prompts/HTML简历编写.md`、`缓冲区/HTML/templates/`。`scripts/` 只在需要批量导出时保留。

**网页视图和打印视图有什么区别？**
`screen` 是连续的响应式网页，适合挂在个人主页上浏览，没有页数概念；`print` 是 A4 纸张预览，应用分页规则，用于投递和打印。两者用同一份 HTML 正文，不复制内容。

## 文档分工

同一件事只在一个文件里写全，其他文件只链接过去，避免几份文档各说各话：

| 内容 | 权威文件 | 其他文件只做 |
| --- | --- | --- |
| 为什么用、理念、能力边界 | `README.md` | 链接 |
| 逐步操作、参数、检查清单、排错 | `使用说明.md` | 链接 |
| 5 步清单 | `使用说明太长人类不看版.md` | README 顶部一行链接 |
| 模板参数与打印设置 | `缓冲区/HTML/templates/README.md` | 链接 |
| 批量导出脚本用法 | `scripts/README.md` | 链接 |
| 提示词内部规则 | `缓冲区/Prompts/*.md` | 不复制 |
