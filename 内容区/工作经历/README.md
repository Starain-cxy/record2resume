# 工作经历

实习与正式工作经历。**材料较少的经历先在别处集中记录，材料一多就拆成独立目录**，不要为整齐而提前拆分。

## 目录约定

```text
内容区/工作经历/<公司或项目名称>/
├── README.md          # 入口：时间、身份、文件清单、公开边界
├── 个人工作内容.md     # 你实际做了什么（最重要的一份）
├── 项目背景.md         # 项目本身在做什么
└── 复盘.md            # 事后判断：哪里有效、哪里失败
```

只有 `README.md` 是必需文件，其余按实际情况添加。目录名用公司名或项目名，不必加日期前缀。

## 每个目录 README 写什么

- 时间范围、地点、你的角色与身份；
- 这段经历在解决什么问题，团队构成与你的职责边界；
- 本目录内各文件的用途，以及应该先读哪一个；
- 公开边界：不能出现在简历或公开版本中的名称、数据、术语。

## 记录原则

- **区分项目在做什么和你在做什么**：团队成果不能默认记成个人贡献。
- **保留失败与探索**：未完成、被否掉、效果不理想的部分也如实记录，写简历时再判断是否使用。
- **不必润色**：这里记录的是事实，包装交给 agent 与模板。

## 示例入口文件

```markdown
# 某公司某项目

- 时间：2025.07 — 2025.09
- 角色：产品与开发实习生（线下）

## 先读哪个文件

1. [个人工作内容.md](个人工作内容.md)：本人实际承担的工作与结果
2. [项目背景.md](项目背景.md)：项目整体目标与团队分工

## 公开边界

项目内部代号、真实数据规模、客户名称不得出现在公开版本中。

## 待核验

（记录不确定的时间、数字或表述，避免直接写进简历）
```
